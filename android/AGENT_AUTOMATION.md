# Native named agents and bounded observations

B19 adds native `AgentControlActivity` and `WaitsActivity`; both are nonexported Android Views screens. Open them from a current Pane action sheet when that owning runtime explicitly advertises `agentAutomation` or `agentWaits`. New also offers a current existing-shell picker for a named start. No browser, SSH, arbitrary RPC or executable picker is involved.

Agent control offers the fixed 24 supported kinds, a bounded name and literal argument lines; rename or clear a name, focus, reviewed keys, reviewed text with keys, and atomic prompt. Herdr launches a fixed supported executable using its existing shell wrapper. This is not a free-form command endpoint. Prompt text, arguments and matched output never enter a Bundle or durable journal. Every prompt/text/key action includes the exact accepted original composer screen; the owning bridge rechecks it immediately before dispatch.

Refresh reviews a fresh original occupant. Census is a read-only named-agent list; its rows do not carry mutation permission. The agent read is bounded ANSI content from the owning runtime, rendered as selectable native plain text without links or automatic file discovery. Explain displays only selected bounded metadata. Missing capabilities or an absent durable connection incarnation show an unavailable/reconnect path.

The action progress distinguishes submission, observed activity and settling. A lost or ambiguous reply leaves an encrypted opaque unknown barrier. Reconcile reads the same server receipt; abandon tracking is an explicit confirmation and does not undo work. Clear settled tracking frees only current settled rows. Stop, retirement and replacement erase private forms/results. Cancellation does not clear another owner's record.

Waits select lifecycle status, bounded output substring/regex, or one of 19 closed scoped event conditions. Available general events use a bounded official subscription equivalence. Output change compares a bounded original visible window once per second; stock Herdr's zero revision remains valid, and unchanged content cannot count as new output. Bounds are 1–300 seconds, 200 output lines, 256 UTF-8 bytes for regex and 1 KiB for substring. A pre-existing output match is an observation; it is not proof that a newly submitted prompt ran. Invalid regex, timeout, interrupted observation, cancellation and replacement remain distinct. Cancel stops the observer only. Rotation/process restoration preserves the original opaque wait ID, owner, incarnation and witness, then polls that ID without another POST.

Stock `events.wait` implements only agent-status matching. General subscriptions provide other emitted event conditions without reconnect/catch-up claims. Original terminal removal cannot be proved by a public-ID-only close/exited envelope; the isolated producer extension below supplies captured original provenance and requires separate review/runtime acceptance.

The implementation targets the currently shipped Herdr v0.9.3 protocol 22 and its exact response variants. It does not promise vendor atomicity: a stock public-target resolver may select a replacement after Collie's final preflight. Such a result stays unknown, never successful or automatically retried. B18/H11 producer and canonical integration, actual local/Crew fake-agent workflows, current harness semantics and physical Pixel lifecycle/font/TalkBack acceptance remain required. JVM AES-GCM fixtures establish authenticated envelope behavior, not actual Android Keystore/provider evidence.

See [ADR 0104](../.adr/0104-named-agent-delivery-and-observation.md) and the [API mapping](./UPSTREAM_API_COMPATIBILITY.md#b19-named-agent-actions-and-waits).


## Original-terminal producer extension

The accompanying isolated v0.9.3 producer source adds two explicit positive `ping` capabilities: `agent_original_input_v1` and `agent_observation_cursor_v1`. Stock v0.9.3 remains unchanged and does not advertise these. This source fork requires ROOT compilation, independent review and actual owned-runtime acceptance before deployment. Neither a capability bit nor the controlled IPC peer proves those gates.

`pane.process_info` may return a private `original_binding` (64 lowercase hex), `original_incarnation` (canonical UUID), and `original_epoch` (canonical u64 decimal string). The binding covers the original runtime, terminal/location, agent/session/name, observed shell/foreground group, and monotonic terminal-role epoch. It is source-private: Crew/native receive only Collie's existing opaque witness. `runtime_incarnation` is available independently for exact exit reconciliation. Missing or partial binding facts cannot authorize guarded dispatch.

On an explicitly negotiated producer, `agent.start`, `agent.rename`, `agent.prompt`, `agent.focus`, `agent.send_keys` and `pane.send_input` carry the original captured `original_binding`. The serialized App resolver checks that original runtime/role/process binding. Queued input retains that same guard through dequeue, every successful write, delayed Enter and completion. Known pre-input retirement returns `original_input_retired_before_input`; any accepted prefix returns `original_input_retired_after_input` and Collie retains UNKNOWN. A stale submission drops only its own remaining bytes, leaving a fresh original submission usable. Foreground process-group checks are observations around write boundaries, not a kernel-atomic compare-and-write guarantee.

A strong event subscription includes the ordinary typed event plus `original.agent_observation { registration_id, pane_id, original_binding, timeout_ms }`. Admission captures the original before tuple and event-hub cursor atomically. The ACK carries `original_observation { registration_id, start_sequence }`; each live frame carries the same registration and a strictly increasing decimal `sequence`. Historical/pre-registration frames, foreign registrations, stream loss and cursor overflow cannot complete an observation. Registration is finite (at most 300000 ms) and globally bounded to 64; existing Collie limits remain 8 per owner.

For `pane_closed`, `pane_exited`, `tab_closed`, `workspace_closed` and `pane_agent_detected`, the negotiated live frame adds a closed `original_transition` before tuple: `binding, incarnation, epoch, role_epoch, pane_id, terminal_id, workspace_id, tab_id`. The actual producer captures it before the original effect, and late exit callbacks carry their original runtime tag rather than resolving a successor. Public-ID-only removal is still insufficient. After event delivery, cleanup and journal awaits, Collie rechecks the original paired read owner, old slot and exact runtime or detected result. A different terminal in the original slot always interrupts.

A move requires the existing exact previous pane/workspace/tab tuple and original terminal UUID, negotiated post-registration live ordering, plus destination rereads proving the same original agent/session/process within the original authorized host/session/scope. Closed/detected/moved results carry neutral metadata and the original opaque witness. Native restoration polls the original ID after the old slot disappears and draws the result without creating destination actions, navigation or a new wait. A fresh deliberate review is required for later actions.

All 19 event conditions have consumer paths: lifecycle status uses the shipped wait; output-change uses bounded visible-content/revision observation; available general events use the official stream; original-anchor transitions use this explicitly negotiated extension. Compilation, all actual vendor workflows, scoped Crew, shared B18/H11 integration, process death and physical Pixel/Keystore/font/TalkBack acceptance remain required and unclaimed.
