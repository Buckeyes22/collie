## Scope and coverage

The original local graph covered all commits reachable from 53 refs: 2 local branches, 9 remote-tracking refs, and 42 tags. It contained 526 commits, 7,826 named reachable objects, and 4,069 blobs. No missing object was reported within that graph. The repository remains shallow at commit `2eff683d74511398923d4cb5a5ee7ac4f758ff32`.

An isolated, non-shallow public-fork mirror of `Buckeyes22/collie` at `/tmp/collie-release-full-history.git` added read-only coverage of 69 refs (6 heads, 61 tags, and 2 pull refs), 1,466 commits, and 6,717 blobs. Of the original local 526 commits, 411 overlap this mirror; 115 are local-only and 1,055 are mirror-only, for 1,581 unique commits across both inspected graphs. The mirror does not establish canonical upstream or current remote state, and it does not contain the local-only commits. The original shallow boundary, unreachable objects, refs absent from both sets, and history not advertised by this mirror remain outside coverage. This is not complete Git-history clearance.

Earlier child-scoped fetch and pinned-file attempts failed before retrieval due that execution profile's DNS/socket/config restrictions and cache misses. Those were limitations of that earlier route, not a general network-status finding. The parent later supplied the isolated full mirror and exact pinned license/tree artifacts used below. No credentials or matched values were printed.

The standard-library scanner at [`scripts/audit-android-history-assets.py`](../../../scripts/audit-android-history-assets.py) was used for the original local history, the non-shallow mirror, and the present tracked/untracked, non-ignored worktree. It reports only rule names, repository paths, commit IDs, and counts. The original local history output grouped 465 blob/rule matches into 168 path/rule pairs. The mirror scan covered 1,466 commits and 6,717 blobs and reported 1,153 candidate blob hits in 151 path/rule pairs: 90 workstation-path, 43 tailnet-host, 15 private-IPv4, 2 bearer-value, and 1 private-key-block pair. The 1,514-file worktree scan reported 158 path/rule pairs, including internal reviewer context and this report's absolute repository links. The scanner is a focused indicator scan, not a substitute for a maintained secret scanner. Its patterns cover common key/token shapes, bearer strings, credential assignments, JWT-shaped values, tailnet hostnames, RFC1918 IPv4 addresses, and workstation paths; obfuscation, uncommon formats, and image-embedded values can evade them.

Gitleaks 8.30.1 was run against the original history (454 patch commits scanned), the public-fork mirror (1,271 patch commits scanned), and a copied present worktree (1,514 regular files; zero symlink/non-regular entries were copied). The official Linux x64 release archive was checksum-verified before extracting the data-only binary; the archive checksum and extracted binary digest are distinct. A synthetic, randomized GitHub PAT-shaped control was detected by that binary (`github-pat`); values were redacted. The history scan produced one generic `generic-api-key` finding in documentation, classified below as a configuration-example false positive; the original-history and worktree scans produced no findings.

The Gitleaks 8.30.0 Linux x64 release was also run with merge-inclusive history options (`--log-opts='--all --full-history -m'`). It scanned 1,460 patch commits and 79,365,836 bytes in the public-fork mirror, producing the same single generic API-key documentation finding, and 525 patch commits and 26,225,407 bytes in the original shallow graph, producing no findings. These patch-commit counts are scanner output and differ from the complete graph counts above (1,466 mirror commits and 526 local commits). Its synthetic randomized GitHub PAT-shaped control was detected. A final default-full-rules Gitleaks 8.30.0 worktree run scanned a 1,515-file copy of current non-ignored regular files; no symlinks or non-regular entries were copied, and the generated Python bytecode file was removed before scanning. It produced no findings. The temporary empty ignore file and explicit default configuration were used; allow comments were ignored and reports were fully redacted. The prior focused worktree scan counted 1,514 files and remains a separate result.

These runs corroborate specific scan outcomes across two release versions, but do not establish complete secret detection. An official [Gitleaks issue #2170](https://github.com/gitleaks/gitleaks/issues/2170) reports missed canonical GitHub PAT detections for a v8.30.1 release binary. The local controls demonstrate detection of the synthetic format used in those runs; the upstream report still limits interpretation of Gitleaks coverage. These are corroborating, coverage-limited signals rather than a secret-clearance guarantee. No `trufflehog` or `detect-secrets` run was performed.

Media inventory across the inspected local and mirror trees covered 241 distinct tracked media paths. Across the inspected graphs, visual inspection covered 103 raster blobs (55 tall phone/acceptance captures and 48 other raster assets) and 6 SVG blobs, plus Android vector drawables and font resources. The original local graph contributed 94 raster blobs and 3 SVGs; the mirror added 9 new raster blobs (8 PNG and 1 WEBP) and 3 new SVGs. The nine added raster assets depict Collie branding, icons, or hero artwork. The added SVGs were structurally checked for text, embedded images, and external references, then rendered to PNG and visually inspected in an isolated Chrome run by the primary reviewer. They depict Collie canine-head marks on plain backgrounds or a dark tile; no text, endpoints, transcripts, or private context was observed. No OCR pipeline was used. Acceptance captures are user/session evidence and have a different privacy profile from product artwork.
