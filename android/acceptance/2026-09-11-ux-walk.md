## After the walk (2026-09-11, later that night)

The 193-step walk above was run against builds `8dc5253`..`5a36187` on `feat/android-twa`. After the walk finished, three more defects were fixed, one rule added during the walk was reverted the same night, and the full instrumented device suite was run against the resulting code. None of this is in the ledger above.

### Pairing-code autofill (Bitwarden)

Third-party password managers (Bitwarden confirmed) key off an `EditText`'s `inputType` password variation, not `importantForAutofill`, so `importantForAutofill="noExcludeDescendants"` alone did not stop the pairing-code popup on the setup card. The setup screen's `pairing_code_input` in `android/app/src/main/res/layout/activity_main.xml` now uses `android:inputType="textCapCharacters|textNoSuggestions"` instead of `textPassword`, matching the Settings pairing field's style. Both pairing fields — setup's `pairing_code_input` and Settings' `settings_pair_code` — are confirmed free of any password `inputType` variation; they stay marked `importantForAutofill="no"` / `"noExcludeDescendants"` as defense-in-depth.

### Gboard row-count test

`gboardKeysReachDirectTyping` in `NativeInteractionTest.kt` (androidTest) previously assumed exactly 3 Gboard rows. The S25 Ultra's Gboard can show an extra number row above the letters, which broke that assumption. The test now detects the row count dynamically from the ratio of the letter block's height to the bottom row's height, instead of hard-coding 3.

### Newest-turn landing on a cold-opened busy agent pane

Cold-opening a busy agent pane from a dashboard tap landed at the top of the session instead of the newest turn at the bottom. Root cause: transcript turn text is selectable (`setTextIsSelectable(true)`), which makes each turn focusable, and Android's default `ScrollView` reveals a view the instant it gains focus — so when the body switched from mirror to transcript, Android handed focus to the first (oldest) focusable turn. Fixed by setting `revealOnFocusHint = false` (Kotlin-only property, no XML attribute) recursively over each turn view in `TranscriptBodyView.kt` (`bind()` and `toggleTool()`), on the "Load older" button, and on the mirror's `terminal_text` in `PaneActivity.kt`.

Verified live on the S25 Ultra: cold-launching the app and tapping the first "Working" row on the dashboard now lands on the newest turn of a long transcript, not the top.

### OVERLAY rule: added and reverted the same night, never shipped

Commit `5a36187` added a rule: if Claude/Codex's input box was unrecognized for two consecutive polls, the pane switched to MIRROR and showed "Terminal · a panel is open", meant to catch an unrecognized panel such as `/cost`. This also fired on an ordinary working Claude pane with no visible composer (e.g. waiting on background agents), incorrectly hiding its transcript. Reverted in full by commit `c245142`. Current, correct behavior: an unrecognized panel such as `/cost` is not auto-detected at all — it is visible only when the operator manually taps "Show terminal" in the pane actions sheet.

The ledger step "an unrecognised panel switches the body to the mirror" (under "Coverage for steps the plan moved") records the behavior as it stood against `5a36187` during the walk. That rule never shipped: it was reverted before release, the same night it was added.

This revert was verified by the unit test suite only — it was not confirmed live on the physical S25 Ultra, because the device was unavailable at the time. Do not cite device verification for this revert.

### S25 Ultra instrumented suite

A full `connectedDebugAndroidTest` run passed 58/58 on the physical Samsung Galaxy S25 Ultra (`SM-S938U1`, Android/API 36), run 2026-09-11, against the post-revert build that includes the autofill, Gboard, and newest-turn fixes above.
