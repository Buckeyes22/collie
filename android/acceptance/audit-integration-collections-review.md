## Governing contract and implementation boundary

`/home/chris/git/collie/CLAUDE.md` → *Android fork scope* states that the Android app is an independent native Kotlin client of Collie's HTTP API. It does not use a WebView or native JavaScript bridge. This bounds vendor docs: the bridge adapts harness and multiplexer protocols; Android receives Collie's normalized response.

The current upstream archive baseline is `/home/chris/git/collie/.project-docs/manifest.json` project commit `8cc67d40d6195b5a5189d038ff2ec8409e0692de`; the distinct upstream Collie commit is `632a2bf784045b1e2576da112d89ed21fecc9eeb`. Source inspection confirms the contract boundary:

- `/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/network/WireModels.kt:84-100` models `PaneSummary.agent` as an opaque `String`; it does not deserialize vendor-specific state or command schemas.
- `/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/ui/AgentIcons.kt:7-31` performs presentation-only prefix matching for selected agent names and otherwise returns the generic icon. `/home/chris/git/collie/android/app/src/test/java/com/lateapex/collie/ui/AgentIconsTest.kt:34-74` pins supported aliases and generic fallback.
- `/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/ui/ShippedAgentCommands.kt:3-21,206` contains a finite native command catalog; it has no entries for Kimi, Qwen, Copilot, Goose, Gemini, Crush, Cursor, Prime, or Muse. `/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/ui/ComposerActions.kt:50-64` supplies server-provided operator commands where present and otherwise uses only the shipped catalog.
- On the bridge, `/home/chris/git/collie/bridge/mux/agents.ts:12-32` defines the ten accepted harness identifiers (`agy`, `antigravity`, `claude`, `codex`, `grok`, `hermes`, `muse`, `omp`, `opencode`, `pi`) plus `shell`; other identifiers are refused by mux conformance. `/home/chris/git/collie/bridge/journal/registry.ts:35-80` builds journals for Claude, Codex, pi, OpenCode, Grok, Hermes, Muse, and the `omp`→`pi` alias. `/home/chris/git/collie/bridge/harness-launch.ts:42-67` offers only Claude, Codex, OpenCode, pi, OMP, Grok, Hermes, Muse, and AGY for launch. Thus there is no general vendor SDK/protocol surface in the native app.
- Tern and TUIOS are multiplexers, not harness names. `/home/chris/git/collie/bridge/mux/registry.ts:1-20` makes that separation explicit; Android has no Tern/TUIOS client. The bridge translates those daemon APIs into the same pane/space HTTP models.
