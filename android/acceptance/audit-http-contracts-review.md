# Android HTTP contract audit

Date: 2026-10-10  
Scope: every method declared by `CollieApi` and every implementation in `CollieApiClient`, compared with current bridge dispatch, auth gates, route handlers, wire types, and existing client tests. This is a source audit only; no request was sent to a live bridge and no terminal/operator operation was performed. Tests were inspected, not run.

## Overall disposition

The implemented `CollieApiClient` routes match the current bridge's HTTP surface and the referenced response models for the reviewed calls. The bridge's global `/api/` pairing gate plus per-route access gate protects all API calls other than open health and pair. Session/host scope is present for the APIs tied to pane/workspace state. Mutations include `Origin`, are marked one-shot, and client redirects/retries are disabled. Endpoint-specific client timeouts fit the bridge behavior: 10 seconds for reads, 20 seconds for ordinary requests, 100 seconds for worktree creates against a 90-second bridge request budget, 60 seconds for uploads, and an 80-second-plus-uplink-derived STT budget.

One least-privilege issue is confirmed: `standbyUpdate()` attaches the paired bearer through the generic request builder, but `/standby/update` is explicitly an unauthenticated, read-only route on the separate standby listener. This header is unnecessary and exposes the bearer to a distinct listener/proxy path. Proposed correction: construct this one GET without `Authorization`; keep the ordinary API bearer behavior intact. Update the existing standby transport test to assert the header is absent while preserving path, response decoding, and idle/active validation. No evidence shows the standby handler uses or logs the bearer.

A legacy `crew()` fallback to `GET /api/pack` remains. The current bridge implements `GET /api/crew`, not `/api/pack`; the fallback runs only after a 404 other than code `crew.not_lead`, and appears intended for older bridge compatibility. On current bridge, normal successful `crew()` never calls it. This is redundant compatibility behavior, not a current route mismatch; preserve only if supporting that older bridge remains intended.

## Cross-cutting contract

- Local request construction is in `/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/network/CollieApiClient.kt:675–833`: all requests set `Accept` and `X-Requested-With`; a nonblank saved token becomes `Authorization: Bearer …`; every POST also sets `Origin` to scheme and authority. `scopedUrl` appends `host` then `session`; path segments and query values are encoded. The default OkHttp client disables redirects and connection retries. Coroutine cancellation cancels the underlying `Call`; response bodies are consumed within `Response.use`.
- `/home/chris/git/collie/bridge/server.ts:1971–1997` makes `GET/HEAD /api/health` open and applies `apiFrontGate` to every other `/api/*` route before dispatch. The global gate requires pairing even for reads. Route-specific `guard` then applies the route's access level, same-origin checks, optional trusted device-header policy, and device write authorization. The normal `/api/pair` exception is implemented at `/home/chris/git/collie/bridge/server.ts:2706–2784`.
- Session-scoped route resolution and `host` forwarding are handled in `/home/chris/git/collie/bridge/server.ts:1999–2015,2050–2115`; `?session=` is a registry key, `?host=` resolves a known crew member, and unknown identities return 404. Snapshot is specially merged and never forwarded as an ordinary route (`/home/chris/git/collie/bridge/server.ts:2118–2157`).
- `/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/network/CollieApiClient.kt:675–755` decodes only successful JSON after recognizing redirects and HTTP failures; error bodies preserve HTTP status, code, bounded message, and `textDelivered`. The bridge's action wire contract is `/home/chris/git/collie/bridge/types.ts:1039–1061`; generic action failures may be 409, and partial reply failures can set `textDelivered` so clients do not duplicate already-typed text. `202` is treated as successful by OkHttp's `isSuccessful` behavior and is used for update acceptance.
- Unknown additive fields are accepted by the app's configured serializer; required response fields are checked by Kotlin serialization and additional invariants in `requireContract`. The client recognizes 304 only on history/chat/pane flows configured to allow it. Bridge error shape is JSON for coded errors and sometimes plain text for malformed inputs; the client handles both.

## Contract edge checks and test gaps

- Pairing 400 behavior is deliberately distinct: server's `parsePairRequest` requires nonempty code up to 64 characters and normalizes/limits label; client converts JSON 400 into `PairResult.Refused` instead of generic HTTP failure. Successful response requires nonblank token/label and rejects control/non-ASCII token characters before repository storage (`/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/network/CollieApiClient.kt:240–266`).
- Pairing is the only API POST without an existing bearer; all regular GETs and POSTs receive it when present. Pairing bodies are excluded from diagnostic capture. `Origin` is attached to POSTs, including read-level POST routes such as refresh and preferences; bridge guards apply same-origin policy.
- Worktree handlers accept 90 seconds server-side; the Android call timeout is 100 seconds. `executeWorktreeOpen` applies this to both folder and workspace routes (`/home/chris/git/collie/android/app/src/main/java/com/lateapex/collie/network/CollieApiClient.kt:639–646`). Upload is 60 seconds; STT uses 80 seconds plus rounded-up uplink time. These are client call timeouts, not verified end-to-end on a device in this pass.
- Most existing route-path/body tests use `MockWebServer`, which proves Android serialization and request construction but does not execute the bridge. Bridge route/parser tests are separate; this audit inspected handlers but ran neither suite. No live bridge, credential, proxy, or device test was performed.
- No API method exists for native push subscription (`POST /api/subscribe`), notification cache-watch routes, update dismissal, launch-row management/recent-run/folder routes, workspace/pane file browsing, changes, blobs, or mux assets.
