# Instrumentation test isolation follow-up

Date: 2026-10-10. Read-only review of the current changes to `NativeLaunchSmokeTest`, `PhysicalLiveReadAcceptanceTest`, and `AndroidKeystoreConnectionStoreTest`. No tests/builds were run, no real connection credentials were read or printed, and no live origin was probed.

## Disposition

The three reviewed corrections close the shared-preference, Android Keystore alias, and saved-connection mutation hazards identified in the previous test audit. I found no remaining test code path in these three files that clears or overwrites an operator’s real saved pairing. This is a source-level conclusion; the instrumentation tests remain unexecuted in this review.

- `/home/chris/git/collie/android/app/src/androidTest/java/com/lateapex/collie/ui/NativeLaunchSmokeTest.kt:26-41` now captures the installed `ConnectionStore.connection.value`, clears the connection only for the launcher assertion, and restores the original value in `finally` (`save(original)` or `clear()` if originally absent). This encloses `ActivityScenario` construction and all assertions, so an assertion/launch failure still reaches restoration. It no longer directly clears the production-named SharedPreferences file. The test remains limited to proving the setup surface/default origin/no-WebView state.
- `/home/chris/git/collie/android/app/src/androidTest/java/com/lateapex/collie/ui/PhysicalLiveReadAcceptanceTest.kt:22-48` now skips unless `liveOrigin` is provided and the already-installed connection is paired and its validated/normalized origin equals the argument. It launches the existing app connection and performs no setup/connect action, no `ConnectionStore.clear`, no credential replacement, and no test-side write. Thus the test is appropriately opt-in and read-only by source. It still requires the operator to intentionally run instrumentation against a disposable/live-readable paired server; this source review did not use or inspect any such credentials. Its pass proves the dashboard produced at least one pane for that invocation, not write authorization or terminal response semantics. Invalid `liveOrigin` syntax throws from `requireValid` rather than becoming an assumption skip; that is reasonable configuration failure behavior but can be made clearer with an assertion/message if desired.
- `/home/chris/git/collie/android/app/src/androidTest/java/com/lateapex/collie/data/AndroidKeystoreConnectionStoreTest.kt:19-40` wraps the application context and prefixes every SharedPreferences name with `instrumentation-isolated-`, so its `EncryptedConnectionStore` cannot read, clear, or write the app’s normal `collie_connection` preferences. It creates a unique per-instance key alias using a UUID, uses the same cipher instance for round-trip, and clears only isolated preferences plus deletes that alias in `@After`. The tested secret/origin are fixed dummy fixture values. This addresses the previous issue where test setup/cleanup reached app-shared preferences and the default production Keystore alias. Cleanup is safe if the alias was never generated because `deleteEntry` on a missing alias is a no-op; no static alias remains in this test.

## Residual validation limits

These changes were reviewed as source only. No Gradle build or instrumentation runner verified AndroidJUnit lifecycle ordering, device Keystore behavior, or exception cleanup at runtime. The previous dated emulator/TalkBack results in `/home/chris/git/collie/android/validation/hardening/README.md` and Android acceptance reports concern their recorded candidates; they do not validate these later test edits. Parent’s current final gates are separate evidence and should be reported from their actual results.

The three tests now isolate app preferences and credentials on their stated paths. They do not make arbitrary instrumentation execution harmless to all device state: the opt-in live read will still issue normal bridge read requests, and Android may retain ordinary app/UI/cache state unrelated to the connection store. Keep it opt-in as currently documented and use only the configured paired origin whose read access is intended for acceptance.
