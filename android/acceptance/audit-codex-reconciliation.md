# Codex accepted-message preview and journal reconciliation

This is a read-only audit of the accepted-message UI lifecycle, Codex transcript adapter, live-chat window, and `/api/pane/:id/chat` contract. It uses source, unit fixtures, and the pinned Codex checkout only. No real session was accessed, no terminal input was sent, no source was changed, and no tests/builds were run.

## Finding: accepted preview is Activity-owned, short-lived, and cleared by unrelated output

**Confirmed visibility defect.** After a successful Codex send guard, Android clears its draft and shows `You sent: …` as the only visible echo until the terminal mirror changes. `PaneActivity.render` removes that preview on any pane `revision` or `text` difference from the baseline (`android/app/src/main/java/com/lateapex/collie/ui/PaneActivity.kt:1344-1347`), and the `clearPendingSent` runnable removes it unconditionally after 6 seconds (`:191-194`, timeout constant `:4030`). The existing Robolectric test explicitly codifies “until the mirror changes” and checks that *any* text/revision update hides it (`android/app/src/test/java/com/lateapex/collie/ui/PaneActivityTest.kt:836-854`). This is insufficient for Codex: its local UI queue can consume the composer without adding a journal row, while unrelated output changes the mirror. The Android preview then disappears even though no matching transcript user turn or queued item is available to the user.

The preview is not durable UI state. `PendingReplyAttempt` and `PendingSent` are private `PaneActivity` fields (`PaneActivity.kt:155-156`, `:3995-3996`); `onSaveInstanceState` saves attachment/presence values but not either preview (`:363-370`). `onDestroy` removes all callbacks and destroys the activity-local data (`:394-400`). A configuration recreation retains the `PaneViewModel` through `ViewModelProvider`, but not these fields. The ViewModel emits `clearReplyDraft = true` only transiently and the Activity acknowledges it immediately (`PaneViewModel.kt:274-279`; `PaneActivity.kt:1443-1460`; reset at `PaneViewModel.kt:876-877`). Therefore a rotation after the successful response can preserve the cleared draft while losing the preview. Process recreation has the same loss. This lifecycle behavior is not covered by the current preview test.

There is also a race in the current owner: any rendered `state.error`/`mutationError` clears `pendingReplyAttempt` (`PaneActivity.kt:1349`). If an ordinary poll error renders before a successful send result, later `clearReplyDraft` cannot create a preview because the attempt has already been dropped (`:1443-1453`). A connection change cancels the in-flight ViewModel mutation and resets pane/transcript state (`PaneViewModel.kt:135-165`); the Activity-local attempt is not tied to a connection identity. An already-created preview can survive a connection change only until its six-second timeout, but it is neither safely reconciled against the old host nor retained when returning to it.

The success language overstates the available evidence. `PaneViewModel` sets `status = pane_reply_sent` on `response.ok` (`PaneViewModel.kt:272-279`; string `android/app/src/main/res/values/pane_strings.xml:199`). For Codex, `CodexReplyGuard` accepts an empty composer region after Enter as consumption (`android/app/src/main/java/com/lateapex/collie/ui/terminal/CodexReplyGuard.kt:39-48` as previously audited). In pinned Codex source, Enter can return `InputResult::Queued` after flushing a paste burst and clearing the visible composer (`/tmp/collie-codex-upstream-20261010/codex-rs/tui/src/bottom_pane/chat_composer.rs:3131-3195`); the normal submitted branch is separate (`:3210-3247`). `input_flow.rs:49-94` then queues either `Queued` or, for some session/turn/recovery states, `Submitted`. Empty composer proves the message left the editable field; it does not prove model dispatch or completion. This matches Codex source revision `c3d3b142d10f4316b46e35aad7e5317e7e506cb7` (checkout `/tmp/collie-codex-upstream-20261010`).

### Concrete native design

Move accepted-message ownership into `PaneViewModel` as a pane- and server-scoped state object, rather than copying an Activity-local `PendingReplyAttempt` into a timed `PendingSent`. For Codex, name its state honestly (for example `AcceptedByCodex(text, since, reconciliation)`), and have the UI say **“Accepted by Codex; waiting for the transcript”** while no matching journal turn exists. This must not be worded “sent” or “running.” Do not automatically replay or retype the message: the terminal already consumed it, and retrying risks a duplicate.

Capture a reconciliation baseline at acceptance from the held `LiveChatWindow` (`gen`, `rev`, `head`, and the set of held user-turn UUIDs). Reconcile only when a later live-chat response is available for the same pane address and same server origin, has the same generation and a strictly later revision, and includes a *new* (`uuid` not in baseline, `seq > baseline head`) `role == "user"` turn whose complete text payload matches the submitted text after only the documented outgoing normalization (`trimEnd`, and the attachment prefix if applicable). Do not match assistants, substring matches, old turns, abandoned entries, older-page results, an unchanged 304, or a response from a different origin. Consume the preview only on that evidence. Keep it on unavailable/no-session/no-log/404/network failures, unrelated pane revision/text updates, empty Codex queue, and queue disappearance. If the generation changes or the baseline was not established before acceptance, stay conservative and keep the accepted state visible until a later unambiguous match or an explicit user dismissal; do not infer delivery from a new tail containing an identical historical message.

There is no message id in the current POST reply contract, so matching exact newly-upserted text is the strongest available correlation, not cryptographic proof of causation. Two identical messages independently submitted after the baseline are inherently ambiguous. If strict causal proof is required, it needs an additive idempotency/correlation token carried by the Android reply request and surfaced in the journal; Codex's existing local queue does not expose such an id. Keep this limitation explicit rather than clearing on a heuristic.

Store this state in `PaneViewModel` so it survives configuration changes. Bind it to `Connection.origin + Scope(host, session) + paneId`, never token or connection `toString()`; `Connection` intentionally has no data-class `toString/copy` that can leak bearer data (`android/app/src/main/java/com/lateapex/collie/domain/Connection.kt:14-26`). On connection switches preserve the old origin's accepted item as suspended, do not reconcile it against the newly selected server even if pane IDs/text coincide, and resume only when the original origin/address is active. For process recreation, use the lifecycle's saved-state mechanism if retaining this potentially sensitive text is appropriate, or explicitly document the process-death boundary; do not silently rehydrate it as an unsent draft. A distinct accepted state must not re-enable Send or enter the draft persistence path.

For non-Codex agents, retain their existing confirmation behavior unless a separate audit establishes a similar gap. The design does not make transcript availability a condition for accepting input: the mirror guard remains the write gate; the journal is only a later reconciliation signal.

## Reconciliation and lifecycle regression cases

Add focused tests before changing implementation:

1. **Unrelated output:** successful Codex acceptance creates the preview; change pane text and revision several times without changing transcript; preview and accepted wording remain visible after the old six-second interval. Assert no additional `reply`/`submitReply` call occurs.
2. **Positive reconciliation:** start with baseline `(gen, rev, head)` and old user entry; after send, merge a later same-generation revision with a new exact user entry and larger `seq`; remove the preview exactly once.
3. **Old identical turn:** the baseline already contains an exact same-text user turn; a later page that only re-upserts/returns that old UUID/sequence, a fresh generation's tail, or an older page must not clear accepted state.
4. **Near misses:** assistant text, partial/substring text, different whitespace beyond `trimEnd`, `abandoned=true`, same/older revision, unchanged 304, unavailable journal, queue `[]`, and queue removal must retain the preview.
5. **Duplicate-text ambiguity:** two new identical user turns after the baseline must not be mistaken for two independently accepted sends; specify deterministic single-match behavior and preserve correlation limitations.
6. **Lifecycle:** recreate `PaneActivity` on the same `ViewModelStore` after success and verify the accepted state/wording remains; separately test process saved-state behavior or the explicitly documented loss boundary. Verify no stale transient `clearReplyDraft=true` clears an unrelated newly typed draft after recreation.
7. **Connection/pane scope:** switch origin while pending, deliver same text/pane id from the other server, and verify no reconciliation; return to original origin and reconcile its later matching user row. Also verify another host/session/pane is isolated.
8. **Race/error:** poll `state.error` during send verification, then return a successful Codex acceptance; preserve the accepted state. A genuine send failure before consumption retains the editable draft and does not create an accepted preview.

The ViewModel-level reconciler should be a small pure unit with explicit fixtures for entries and baseline identity. Activity Robolectric tests should cover display/lifecycle; ViewModel tests should cover connection and write-count invariants. No integration test should submit to a real Codex process.

## Coverage limits

Source review and fixture inspection only. No unit tests, Robolectric/device tests, emulator, real Codex process, live Collie API, or server integration were run. The Android test named `verifiedSendShowsEchoGapPreviewUntilTheMirrorChanges` proves only its current broad-clear rule, not its suitability for a locally queued Codex message. The bridge's Codex steer test proves the eventual transcript shape, not how long before that row appears. Exact-text/new-turn reconciliation is still a best-effort correlation until the request and journal share a durable id; the accepted preview should remain honest and never trigger automatic resend.
