## Notices, SBOM, generated code, and checker accuracy

- `/home/chris/git/collie/scripts/android-sbom.ts` parses only lock rows containing `releaseRuntimeClasspath`, validates Maven coordinates/duplicate keys/version/hash formats, sorts the modules, and labels the BOM as CycloneDX 1.6. It explicitly marks composition incomplete and states that build/test tools, bundled assets, dependency edges, and license data inferred from a lock are excluded. This is an honest **locked build-input inventory**, not a claim about the final R8-retained APK contents. Release packaging hashes the signed APK and includes the generated SBOM, dependency notices, third-party artwork notices, and font license files.
- `/home/chris/git/collie/scripts/android-dependency-notices.ts` uses the same 80-module runtime filter. It chooses the longest matching license-map prefix, fails when an artifact has no map rule, includes every coordinate/version/source, adds the Apache-2.0 text once, and adds the OkHttp Public Suffix List MPL-2.0 note. The checked-in `/home/chris/git/collie/android/app/src/main/res/raw/dependency_notices.txt` matched generated output in `--check` (exit 0). The direct test `/home/chris/git/collie/scripts/android-dependency-notices.test.ts` asserts generated bytes equal the checked-in notice and missing license maps fail.
- `/home/chris/git/collie/android/dependency-licenses.json` maps all 80 runtime modules by exact group prefixes; `androidx.*`, Material, Error Prone annotations, Guava listenablefuture, OkHttp/Okio, Kotlin, coroutines, serialization, JetBrains annotations, and JSpecify are all mapped to Apache-2.0. OkHttp's PSL is separately named. The release does not package test-only Hamcrest's BSD license because Hamcrest is absent from runtime. The separate `/home/chris/git/collie/android/app/src/main/res/raw/third_party_notices.txt` handles artwork and its distinct MIT, CC-BY and Apache notices; Aldrich and JetBrains Mono font licenses are separate raw resources. Those assets are intentionally outside the lock-based SBOM and are not treated as Gradle modules.
- Generated code: Kotlin serialization serializers and Android View Binding classes are generated during compilation and are not vendored source. Their compiler/build tools appear in non-runtime lock configurations. R8 minification and resource shrinking are enabled; consequently, the SBOM's limitations correctly say that it includes modules potentially removed from the APK.
- `/home/chris/git/collie/scripts/check-android-native.ts` checks exact plugin/wrapper/application/API/toolchain pins, expected direct dependency declarations, lock-all-configurations, and that at least one nonempty lockfile exists. It does not independently parse the lockfile to prove every direct dependency/version is present or compare its full graph against the installed inventory. The actual Gradle lock and release-notice check provide that evidence elsewhere; treat this script as a native policy/configuration checker, not a dependency-graph consistency verifier. No incorrect claim in its CLI output was observed.
- No Firebase Messaging, Google Services plugin, push SDK, HTTP logging library, generated API client, or vendored third-party app Java/Kotlin source is present. Native push remains an unsupported/not-shipped feature: only the payload decoder exists; no provider, registration, delivery service, credential, durable sequence store, channel, or notification permission flow is implemented, as `/home/chris/git/collie/android/NATIVE_PUSH_CONTRACT.md` explicitly says.
