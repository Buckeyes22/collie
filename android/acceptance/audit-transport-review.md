## Requirements extracted and compared

- Native Android is an independent Kotlin REST client of Collie's existing HTTP API; no WebView, browser bridge, Herdr socket protocol, or direct agent-server protocol. The front-end docs also require verified TLS, encrypted pairing credentials, and conservative terminal write gates (`/home/chris/git/collie/CLAUDE.md` → Android fork scope; `/home/chris/git/collie/.adr/0036-the-android-app-is-a-native-rest-client.md`; native implementation plan).
- Pairing is open only at `POST /api/pair`; all other API routes, reads included, require a paired bearer, except open health. Pairing request/response bodies must never be captured. Writes must not be retried automatically; redirects must not be followed. `/home/chris/git/collie/bridge/server.ts:1993–1996,2705–2777`; `/home/chris/git/collie/bridge/pairing.ts:324–332`; `/home/chris/git/collie/bridge/types.ts:1039–1061`; `/home/chris/git/collie/.adr/0086-reads-need-the-pairing-token.md`.
- Origin validation must preserve an HTTPS mount and reject credentials, ambiguous path segments, query, and fragment; write `Origin` is scheme plus authority. See native compatibility doc and route gate implementation (`/home/chris/git/collie/bridge/server.ts` and `/home/chris/git/collie/bridge/access-jwt.ts`).
- Cancellation must cancel the underlying HTTP call; response bodies are closed after parsing. OkHttp must keep TLS certificate/hostname verification and not follow redirects or retry unsafe mutations. Time budgets are endpoint-specific.
- Pairing bearer persistence is encrypted with a non-exportable Android Keystore AES/GCM key; invalid/unreadable records fail closed and are synchronously removed. Diagnostic capture is opt-in, bounded, encrypted after rollover, and pairing bodies are excluded. App-private/cache output is shared only by explicit export flow and cleaned after process recovery.
- Unknown additive wire fields remain forward-compatible; malformed successful response evidence is a protocol failure. HTTP error codes and `textDelivered` are retained so uncertain terminal-send outcomes are not automatically replayed.
- Native push payload parsing is only a pure validation contract. Provider authentication, registration, sequence persistence, notification display and delivery are explicitly not implemented (`/home/chris/git/collie/android/NATIVE_PUSH_CONTRACT.md` → Current implementation, Proposed registration and delivery boundary).
